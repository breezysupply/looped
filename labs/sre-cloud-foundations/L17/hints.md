# L17 hints (four rungs; rungs 3–4 end independent credit for this attempt)

1. **Boundary.** Sort the symptom into a phase before touching YAML: never scheduled (Pending, no node assigned), scheduled but killed while running (restarts, a termination reason), or waiting on something it needs (a volume, a budget). Each phase has its own owner: the scheduler, the kubelet and kernel, the volume provisioner, the eviction API.
2. **Evidence source.** `kubectl -n beacon get pods -o wide` first; then `kubectl describe` on the pod or PVC and read the Events at the bottom (`FailedScheduling`, `ProvisioningFailed`, `Back-off restarting`). `kubectl get pod <p> -o jsonpath='{.status.containerStatuses[0].lastState}'` shows the previous termination. `kubectl get nodes -o custom-columns=NAME:.metadata.name,CPU:.status.allocatable.cpu,MEM:.status.allocatable.memory` gives capacity; `kubectl get storageclass` and `kubectl get pdb` give the rest.
3. **Discriminating check.** Compare numbers, not impressions: the request against node allocatable; the memory limit against the working set the process actually needs (`kubectl exec` and read `/sys/fs/cgroup/memory.current` once it runs with a generous limit); the PVC's `storageClassName` against the classes that exist; the PDB's `disruptionsAllowed` against the pods a drain must evict.
4. **Root cause and fix.** A: the API asks for 64 CPUs; restore a request close to real use (100m). B: the report needs ~110 MiB resident and the limit is 64Mi, so the kernel kills it; set request ~128Mi and limit ~160Mi, never remove the limit. C: `fast-ssd` does not exist here; volumeClaimTemplates are immutable, so delete the StatefulSet and the Pending PVC, apply with `standard`, run `assets/restore-dataset.sh` and compare the checksum. Drain: minAvailable 2 with 2 replicas allows 0 disruptions; scale the API to 3 (or use maxUnavailable: 1 with 3 replicas) and drain again — never `--disable-eviction` or delete the budget. D: 64Gi requests cannot fit any node; right-size the request and the data survives on the same PVC.
